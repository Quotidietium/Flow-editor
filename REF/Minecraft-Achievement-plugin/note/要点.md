# 项目要点

本项目是一个示例插件（ExampleAchievements），演示如何用 **Java 21 + Paper 1.21.11**
在原版进度界面（Esc → 进度）中添加一个**独立标签页**形式的自定义成就系统。

## 架构总览

```
插件 jar（Paper 插件，paper-plugin.yml）
├── paper-plugin.yml                 # 声明 main + bootstrapper + api-version（必填）
├── datapack/                        # 内置数据包（由 bootstrapper 注册）
│   ├── pack.mcmeta                  # min_format/max_format: 94（1.21.11 新式写法）
│   └── data/exampleach/advancement/ # 8 个进度 JSON（1.21 起目录名单数）
│       ├── root.json                # 根进度 = 标签页本身
│       ├── first_join.json …        # 6 项插件授予的成就
│       └── completionist.json       # "大满贯"（6 项条件汇总）
└── com/example/achievements/
    ├── ExampleAchievementsBootstrap # 数据包发现注册（最早启动阶段）
    ├── ExampleAchievementsPlugin    # 主类：装配 + 命令注册 + 自定时报表
    ├── Achievement                  # 成就枚举（id ↔ 显示名）
    ├── AchievementService           # 查询/授予 Advancement
    ├── ProgressStore                # 玩家计数 YAML 持久化（脏位 + 定时落盘）
    ├── AchievementListener          # 事件 → 计数 → 达标授予
    └── ExampleAchievementsCommand   # /exampleach 进度查询（BasicCommand）
```

## 关键技术点（含出处）

1. **插件内置数据包：Paper Datapack discovery 生命周期 API**
   - 把数据包放进 `src/main/resources/<目录>/`（本项目为 `datapack/`），通过
     `LifecycleEvents.DATAPACK_DISCOVERY` 事件调用
     `event.registrar().discoverPack(uri, id)` 注册，最终数据包名为
     `ExampleAchievements/provided`，无需向世界 `datapacks/` 目录解压任何文件。
   - 官方文档：<https://docs.papermc.io/paper/dev/lifecycle/datapacks/>、
     <https://docs.papermc.io/paper/dev/lifecycle/>
   - 事件所有者类型是 `BootstrapContext`：**只能**在 bootstrapper 中注册，
     普通 `JavaPlugin` 无法注册该事件（javap 确认泛型约束）。
   - 数据包发现发生在服务器加载世界（选择启用数据包）阶段，早于插件的
     `onLoad/onEnable`，因此注册放在 `PluginBootstrap` 中。

2. **必须使用 paper-plugin.yml 而非 plugin.yml**
   - `bootstrapper:` 键只在 paper-plugin.yml 中受支持；写在 plugin.yml 里会被
     **静默忽略**（实测：bootstrap 不执行、数据包不加载、无任何报错）。
   - paper-plugin.yml 中 `api-version` 为**必填**（缺失时 Configurate 报
     "A value is required for this field"，插件直接加载失败）。
   - 后果：Paper 插件不能用 plugin.yml 的 `commands:` 声明命令，需在主类
     `getLifecycleManager().registerEventHandler(LifecycleEvents.COMMANDS, …)`
     中用 `registrar().register(label, description, aliases, BasicCommand)` 注册；
     `COMMANDS` 事件的所有者是 `LifecycleEventOwner`，主类即可注册。
   - 迁移即变成 Paper 专属插件（不能在 Spigot 上加载），对本项目可接受。

3. **数据包格式版本（1.21.9+ 的新机制）**：1.21.11 的 data pack format 为
   **94.1**（主版本 94 + 次版本 1）。自 25w31a 起推荐/要求（format > 81 时强制）
   使用 `min_format` / `max_format` 字段代替 `pack_format`：

   ```json
   { "pack": { "description": "…", "min_format": 94, "max_format": 94 } }
   ```

   只写 `pack_format: 94` 会报
   "Pack declares support for version newer than 81, but is missing mandatory
   fields min_format and max_format"（实测数据包仍会加载，但有报错）。
   来源：<https://minecraft.wiki/w/Pack_format>

4. **成就目录名**：自 1.21（24w21a）起，`advancements/` 目录更名为单数
   `advancement/`。来源：<https://minecraft.wiki/w/Advancement>

5. **"只由插件授予"的标准做法**：所有子进度的 criteria 使用
   `minecraft:impossible` 触发器（原版永不触发、无 conditions），只能通过
   Bukkit API `AdvancementProgress#awardCriteria(String)`（或 `/advancement grant`
   命令）授予。来源：<https://minecraft.wiki/w/Advancement/JSON_format>
   - 根进度用 `minecraft:tick`：服务端每 tick 自动为玩家补授，保证标签页对
     所有玩家立即可见（标签页只有在树中至少一项进度被授予后才显示）。
   - 根进度 `display.background` 必须给纹理路径，否则标签页背景为紫黑棋盘。

6. **Paper 1.21.11 API 迁移点**（相对旧教程的变化，编码时踩过）：
   - `PlayerAdvancementFinishedEvent` 已更名为 `PlayerAdvancementDoneEvent`
     （`org.bukkit.event.player`）。
   - `Advancement#getKey()` 现返回 adventure 的
     `net.kyori.adventure.key.Key`（用 `namespace()` / `value()`），而非
     `org.bukkit.NamespacedKey`（`Bukkit.getAdvancement(NamespacedKey)` 仍接受
     NamespacedKey）。
   - `PlayerAdvancementDoneEvent#message(Component)` 可覆盖默认英文播报。

7. **播报与音效**：advancement JSON 中 `announce_to_chat` 设为 false，改由
   `PlayerAdvancementDoneEvent` 监听器调用 `event.message(Component)` 输出中文
   播报，并播放 `ENTITY_PLAYER_LEVELUP` 音效；`show_toast` 保持 true，弹出原版
   成功提示（toast 由授予动作自动触发）。

8. **"大满贯"汇总成就**：`completionist.json` 定义 6 个 impossible 条件
   （与 6 项成就的 id 同名）。每完成一项普通成就，监听器调用
   `awardCriterion(player, COMPLETIONIST, 成就id)` 补齐对应条件，全部补齐时
   原版自动判定完成并给予 `rewards.experience`。

9. **进度持久化**：`ProgressStore` 在内存 `ConcurrentHashMap` 中累加计数并置
   脏位，`runTaskTimer` 定时（默认 300s，可配置）+ `onDisable` 时统一写
   `plugins/ExampleAchievements/progress.yml`，避免高频事件（挖方块）直接刷盘。

## 构建与冒烟测试（实测记录）

- 构建：`mvn package` → `target/ExampleAchievements-1.0.0.jar`（Java 21 目标
  字节码，`maven.compiler.release=21`；本机用 JDK 25 编译亦兼容）。
- 依赖：`io.papermc.paper:paper-api:1.21.11-R0.1-SNAPSHOT`（scope provided），
  仓库 <https://repo.papermc.io/repository/maven-public/>。
- 冒烟测试（Paper 1.21.11 build 132，`run/` 目录，已 gitignore）：
  - `Loaded 1592 advancements`（vanilla 1584 + 本插件 8，全部解析成功）；
  - `/datapack list enabled` 显示 4 个数据包，含
    `ExampleAchievements/provided (plugin)`；
  - 首次启动自动启用（"Found new data pack ExampleAchievements/provided,
    loading it automatically"）；`/datapack list` 触发的重载中
    DATAPACK_DISCOVERY 事件正常重放；
  - 插件日志：`内置数据包加载成功，8 个自定义成就已就绪。`；
  - 控制台执行 `/exampleach` 正确回显"该命令仅玩家可用。"（命令注册成功）；
  - 停服时 `onDisable` 正常保存进度。
- 注意：PaperMC 旧版 v2 下载 API 已下线（HTTP 410 sunset），需使用
  Fill v3：<https://fill.papermc.io/v3/projects/paper/versions/1.21.11/builds/latest>

## 已知限制（示例项目的取舍）

- 成就阈值只在启动时读取（改 config 需重启或 `/reload`）。
- 计数不区分方块/食物/怪物种类。
- `PlayerMoveEvent` 高频触发（达标判定为一次浮点比较，可接受；生产环境可
  改用 Paper 的 `EntityMoveEvent` 或分 tick 采样）。
- 仅适配 1.21.11（min_format/max_format = 94）；跨版本需调整 pack.mcmeta
  并回归测试。
- 未接入真实客户端验证玩家侧 UI（toast/标签页展示依赖原版行为：根进度
  tick 自动授予后标签页即可见）。
