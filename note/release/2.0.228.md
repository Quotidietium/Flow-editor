# 2.0.228

> 发布日期：2026-09-08｜分支：`develop`
> 主题：**WEB UI 舒适度优化循环 167+168**——移动端菜单不抢焦点 + 配置模板菜单搜索/键盘导航
> （双循环批：一个移动端真实缺陷修复 + 一个菜单能力对齐，共享验证）。

## 内容

### 循环 167：移动端打开菜单不再弹虚拟键盘

- 165 给片段菜单加的「打开即聚焦搜索框」在移动端会**弹起虚拟键盘
  把菜单顶出屏**。现在按宽度口径（<768，与编辑页 `isMobile` 一致）
  分流：桌面保持打开即键入，移动端不抢焦点、点按照常工作。
- 插入片段菜单与配置模板菜单（168 新增的搜索框）同规则覆盖。

### 循环 168：配置模板菜单搜索过滤 + ↑/↓ 导航 + 预览联动

- 模板菜单条目渐多（我的模板随攒 + 12 内置四组 + 格式化/重置），
  与片段菜单对齐同款能力：**搜索框键入即筛**（我的模板按名称；
  内置按标签/提示/组名；**动作行同进过滤**——「格式化」Enter 直发）。
- **↑/↓ 虚拟高亮循环导航**（片段菜单同款 combobox 惯例）：焦点不出
  搜索框，Enter 应用高亮模板/执行高亮动作；鼠标悬停与 Tab 聚焦
  同步高亮；`aria-activedescendant` 标注。
- **差异预览改为跟随高亮**：键盘导航时「将修改的叶子键（旧值→新值）」
  实时切换——此前只有悬停/聚焦能驱动，键盘用户预览不到。「最后悬停
  残影」模型随之退役，预览区永远反映当前高亮行；引导文案更新为
  「悬停/↑↓ 选中模板可预览将修改的配置项」。
- 保存模板成功**显式收菜单**（存完多半要回编辑器，与片段菜单一致）。
  排障发现：基线的「保存后菜单关闭」其实靠 bits-ui 焦点外溢**偶然**
  实现——popover 绑上 `bind:open` 后该隐式行为失效，须显式 `open=false`
  - 保存表单 Enter 拦默认（防焦点回跳重开，片段菜单同款坑）。

### 排障笔记

- **「滚动-悬停互追」**：`scrollIntoView` 若由 `$effect` 对所有高亮来源
  （含悬停）触发，在超出 `max-h` 的滚动菜单里会与 Playwright/用户的
  鼠标移动互相追赶（滚动把新行送到指针下 → `mouseenter` 改高亮 →
  再滚动），按钮永不稳定。修正：**只有键盘导航**（`moveActive`）才
  滚入可视区（按 `#id` 直取不等渲染），悬停路径不滚——指针下的行
  本就可见。
- 移动端 e2e 夹具注意：`editPage` 夹具按桌面布局展开示例卡片，移动端
  视口下不可用；且移动端默认停在「预览」半屏，须先 `#editorMode`
  切到「编辑」半屏再等 400ms 滑屏动画（`mobileEditorTools` 同款做法）。
- Monaco 的 textContent 会把行号拼进文本（`123{  "theme": …}`），
  断言别带花括号边缘的空白。
