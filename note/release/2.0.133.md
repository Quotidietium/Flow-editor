> 主题：MC 成就图支持 subgraph 分组——subgraph = 成就栏，代码即分组视图

## 内容

### subgraph 成就栏（mc-advancement 1.5.0）

此前多成就栏靠「互不相连的连通分量」表达，代码里看不出分组。现在
**subgraph 直接映射成就栏**：

- **解析**（插件 parseFlow）：`subgraph id["栏名"] … end` 一级结构；组内
  语句归属 `groupOf`；嵌套按最内层；组 id 作为「组节点」注入（无实体同名
  节点时补一个 label=标题）——nid 规范化/环检测/BFS 全部复用原管线。
- **分析**：每个 subgraph = 一个成就栏；**组 id 强制为栏根**；组内未连线
  的成员自动挂到根下（subgraph 已表达归属，无需画线）；组内环经根可达性
  检测报错；**跨栏连线忽略并警告**（MC 进度不能跨栏承接，成员回落组根）；
  未入组的游离节点仍按连通分量兜底成栏（平铺旧图完全兼容）。
- **生成**（buildCode 可选 groups 参数）：每个栏输出
  `subgraph <根id>["栏名"]` 包住成员与组内边；**栏根不渲染为普通节点**
  （cluster 框即栏，语义也更贴 MC 标签页）；**组 id 参与的边不输出**——
  dagre 不允许边端点即 cluster id（`Setting root as parent of root would
create a cycle`，真实浏览器探针抓到）；读回时未连线成员自动挂根，往返
  语义无损。前端写回与逆向导入产物自动获得分组语法。
- **可视化画布兼容**：主界面画布（model.ts）对 subgraph 行按不支持跳过，
  画布编辑会平铺化显示——但 tab 语义经连通分量完整保留，不丢数据
  （既有取舍，文档明示）。

### 循环 12：闭环 e2e 全量稳定化

闭环用例在全量顺序下偶发 `Execution context was destroyed by a
navigation`——**Vite 依赖预优化在套件中段触发整页 reload**（既有
cold-start gotcha 的另一种现身时机：不在冷启动，而在某个用例首次踩到
未优化依赖时广播 full-reload），恰好打断导入后的轮询。修复：用例开头
主动 `page.reload()` 预热吸收重载 + `test.setTimeout(60_000)`；单跑、
全量均稳定。
