## 审计范围

本轮覆盖三个面：embed iframe 的 sandbox 属性集完备性、`openTextFile`
取消/失败路径的资源清理、legacy redirect 的路由白名单边界。

## 缺陷与修复

**openTextFile 两条泄漏/挂起路径（修复 + 判别性单测）**：
① `change` 事件无文件分支只 resolve 不 `input.remove()`——隐藏 input
滞留 DOM；② `file.text()` 无 catch——文件在选中后被删除/锁定时读取
reject，promise **永远 pending**（调用方 await 永挂、无任何反馈、
input 也滞留）。修复：统一 `finish()` 收口（resolve + remove），
读取失败走 `.catch(() => finish(undefined))`。

fileIO.test.ts 新增 2 用例：无文件 change 后 input 从 DOM 移除；
读取 reject 后 resolve undefined 且 input 清理。判别性验证：暂存修
复 2 用例失败、恢复后 12/12 通过。

**sandbox 完备性钉死（防漂移断言）**：`EMBED_IFRAME_SANDBOX` 与
`embed-loader.ts` 的 `IFRAME_SANDBOX` 两处字面量一致（靠注释约束同
步，有漂移风险）。新增 embedCode.test.ts 断言：snippet 的 sandbox
恰好包含 widget 所需四项能力（scripts/same-origin/popups/
popups-to-escape-sandbox），未来任何放宽（forms/top-navigation/
modals 等）都会被测试拦截。

## 审计通过项

- **sandbox 属性集**：`allow-same-origin` 为 /embed SvelteKit 应用
  boot 所需（隔离靠 /embed 不导入 state 单例，e2e 覆盖）；无
  allow-forms/allow-top-navigation/allow-modals 等过度授权；「编辑」
  链接经 allow-popups 开新窗、不能 top-navigation
- **redirect 白名单**：`LEGACY_ROUTES = {edit, view}` 集合成员检
  查，`/../evil` 等不在集合回退 `edit`；fragment 以 `#` 拼接无路径
  逃逸面；search 原序保留（redirect.test.ts 既有覆盖）
