# 2.0.109

> 发布日期：2026-08-21
> 主题：第 22 轮审计——Monaco 错误标记跨文档误植 + View 卸载后 pan-zoom 复活竞态

## 审计范围

本轮覆盖记录在案的两个候选面：PanZoomToolbar 在 plain/compare 双形态下的
实例绑定与生命周期（结论：工具栏全部走共享 PanZoomState 的可选链调用，
本身安全；但审计牵引出 View 卸载竞态，见下），以及 DesktopEditor
Monaco 双 model 切换的 lastMarkers 失效逻辑。

## 缺陷与修复

**代码错误标记误植到配置 tab（产品缺陷，修复 + 判别性 e2e 钉死）**：
`errorMarkers` 携带的是 mermaid **代码**文档的行列坐标
（`state.svelte.ts` 解析管线产出），但 `DesktopEditor.svelte` 的标记应用
不分 tab 一律设在当前 model 上——切到「配置」tab 时，代码错误以代码坐标
标到 JSON 文档上（实证探测：旧代码下配置 tab 出现 2 条错误波浪线，指向
与错误毫无关系的 JSON 行）。修复：仅当代码 tab（mermaidModel）时应用
errorMarkers，配置 tab（jsonModel）清空；配置自身的 JSON 错误本就由
Monaco json worker 校验呈现，语义各归其位。

e2e 回归（errorDisplay.spec.ts「code error markers stay on the code
tab」）：坏代码→代码 tab 可见波浪线→切配置 tab（先等配置文本渲染再判
0，避免与同 effect 的标记应用竞态——`toHaveCount(0)` 在点击后第一帧立
即判定会漏掉稍后应用的标记）→切回代码 tab 波浪线仍在。已做判别性验
证：暂存修复跑该用例失败、恢复修复通过。

**View 卸载后 pan-zoom 复活（竞态泄漏，修复）**：
`handleStateChange` 中 `renderAndPlaceDiagram` 是异步的；若渲染期间
View 卸载（如切到可视化模式），`destroy()`（第 17 轮加的清理）先执
行，await 返回后 `handlePanZoom`→`updateElement` 仍会在已分离的 SVG
上**重建** svg-pan-zoom 实例并重连 ResizeObserver——恰好把 destroy 刚
清掉的窗口级监听又泄漏回去（下次挂载才会自愈，若用户停留在可视化模
式则一直挂着）。修复：`disposed` 标志，卸载后 await 返回即跳过
`updateElement`。既有 stress-smoke（60 次模式切换无页面错误、无意外
console 错误）覆盖修复后的行为面。

## 审计通过项

- PanZoomToolbar 五个按钮（重置/缩小/放大/全屏）全部经共享
  PanZoomState 的 `this.pzoom?.` 可选链调用，plain/compare 双形态互斥
  渲染下无陈旧引用面
- DesktopEditor lastMarkers 去重（model 引用 + markers 引用双键）在
  code↔config 往返切换下自洽：换 model 强制重刷，同 model 同 markers
  跳过
- MobileEditor 无 marker 管线，不受跨文档误植影响
