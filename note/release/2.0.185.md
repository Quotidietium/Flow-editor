## 内容

### 循环 123：错误横幅恢复力

- **恢复到最近可用版本**：代码改坏后横幅新增直达钮，一键回到最后
  一次解析成功的那份代码——状态网关在每次「mermaid 解析 + 配置
  JSON 均有效」的发布时记录（`state.svelte.ts` 的 `lastGoodCode`），
  粒度为每次有效键击，比历史时间线的 60s 快照细。仅代码错误时
  提供（配置错误保留专属的「重置为默认配置」）；会话中从未有过
  有效版本则不给钮。
- **载入链接中的图表**：把分享链接整串误粘进代码区是高频误操作
  （此前只能对着语法错误发懵或手动拆 URL）——横幅识别后一键走与
  URL 初始化同一条载入链路（`loadState`：反序列化 + 配置安全门 +
  url 源输入管道），预览因 code 变化自动重渲染。识别为纯函数
  `shareLinkHash`（serde.ts）：匹配整段 `scheme://…#pako:…`/`#base64:…`
  或裸 `pako:`/`base64:` 串（serde 类型大小写不敏感），Mermaid 代码
  不可能整体命中该形态，无误报面。

### 测试经验记录

- 恢复语义的断言锚点必须钉在「整段粘贴」的独特文本上：逐字符键入的
  中间态（如 `A --> B `）本身合法，也会成为可恢复版本——这是特性语义
  （回到最后一次能渲染的状态）而非缺陷。
- 本机 `core.autocrlf=true` 使工作区大量文件以 CRLF 检出，`prettier
--check` 全仓（无缓存）报 478 文件——环境级预存状况（git 索引仍为
  LF、`git status` 干净），非本批引入；改动文件均为 LF 且通过 prettier。
