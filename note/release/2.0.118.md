# 2.0.118

> 发布日期：2026-08-21
> 主题：可视化编辑器——空白处直接拖拽平移画布（框选移入修饰键）

## 背景与改动

用户指示：可视化编辑器中点击空白处（未命中节点/连线）时应当可以直接拖动
画布。2.0.89 起画布平移只挂在「空格+拖拽 / 中键拖拽」上，空白左键拖拽被
橡皮筋框选占用——与办公软件画布「空白即抓手」的惯例相反。

本次把手势分层改为：

| 手势                 | 行为（改动前 → 改动后）                   |
| -------------------- | ----------------------------------------- |
| 空白左键拖拽         | 橡皮筋框选 → **平移画布**                 |
| Shift+左键拖拽       | 加选框选 → 框选（**替换**当前选择集）     |
| Ctrl/Meta+左键拖拽   | 加选框选 → 框选（**追加**进当前选择集）   |
| 空格+拖拽 / 中键拖拽 | 平移（不变，保留）                        |
| 空白单击（无位移）   | 清空选择（不变，改经 panning.moved 判别） |

实现要点：

- `panning` 手势增加 `moved` 标志：pointerup 时无位移的空白按下按
  「空白单击」处理（清空选择），与此前亚阈值框选的行为完全一致；
- 框选为何必须让位：同一手势（空白按下并拖动）不能既是平移又是框选，
  平移是更高频的画布导航操作，框选下沉一层到修饰键（draw.io 亦是
  修饰键控制框选的替换/追加语义）；
- 光标提示：画布 svg 常态 `cursor: grab`，平移中 `grabbing`
  （节点/连线/手柄各自光标不变）；
- 空画布提示语同步更新为「拖动空白平移画布（Shift+拖拽框选）」。

## 测试

- `visualEditorUx.spec.ts`：
  - 「rubber band selects enclosed nodes」改为 Shift+拖拽（替换语义——
    新建节点后自带选中态，追加语义会把刚建的节点也圈进删除集，这正是
    区分两种框选语义的判别性场景）；
  - 新增「blank drag pans the canvas; blank click clears the selection」：
    空白左键拖拽断言 scrollLeft/scrollTop 实际滚动；再验证单击节点选中、
    空白单击清空选中（平移后重测节点包围盒再点击）。
- e2e：visualEditorUx 20/20、visualEditor + visualEditorAllKinds 10/10 全绿
  （本机 Windows 11，单 worker）。
- svelte-check 0 错误 0 警告；eslint / prettier 通过。
