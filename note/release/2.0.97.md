## API 逻辑缺陷修复（逐项经复现确认）

1. **disable→enable 后插件静默失效**（registry.svelte.ts）：disable 清空
   运行时实例，enable 的取实例逻辑 `rt ? rt.instance : loadModule(...)` 在
   rt 存在时永远得到 undefined——插件停用再启用后所有钩子消失（页面重载
   才恢复），且 source 为空的运行时注册（测试/嵌入）永远无法恢复。修复：
   disable **保留**已加载实例（钩子分发本就按 enabled 过滤），enable 仅在
   无活实例时从持久化源重载。新增回归单测：disable/enable 循环后钩子仍生效
2. **MCP `export(png-dataurl)` 返回 SVG 冒充 PNG**（editorApi/bridge）：
   旧实现直接把 SVG data URL 当 PNG 返回——AI 调用方拿到错误格式。修复：
   真正光栅化（svg → Image → canvas → PNG，白底 2x），不可用时返回明确
   工具错误；桥 `handleBridgeRequest` 随之异步化。新增 e2e 断言
   `^data:image/png;base64,`
3. **editorApi.getState 恒定 undefined 的死表达式**（`serialized ===
undefined ? undefined : undefined`）与误导致类型 `title?`——清理，
   全局状态访问器类型同步修正

## 测试稳定性根治

- **本机 15 个"预存"单测失败清零**：根因是 Node ≥25 的实验性全局
  localStorage 与 vitest jsdom 冲突（`--localstorage-file` 警告，CI 低版本
  Node 不受影响）。`src/tests/setup.ts` 增加探测式内存 Storage 兜底——
  本机 283/283 全绿（历史首次零失败），CI 真实 localStorage 优先不受影响
- migrations 用例单跑 3.96s 贴近 5s 默认上限，并行负载下超时——放宽至 20s
- **plugins e2e frontend 用例导航缺失修复**：DX 轮清理 unused-var 时误删
  该用例唯一的导航来源（editPage fixture），新 context 停在 about:blank
  导致 90s 等待按钮超时——误诊两轮（dev-server 陈旧模块/顶层 test.slow）
  后定位为纯测试缺陷，恢复 fixture；顺带确认顶层 `test.slow()` 为非法用法
  并移除
- 排查过程中修正一个诊断陷阱：bash 下 curl URL 含 `(app)` 会被 glob 干扰
  管道 grep 造成"服务器陈旧"误报（实际 served 模块是新的）
