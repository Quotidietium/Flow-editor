## Git 编辑器（GitEditor）

gitGraph 的模型是「按序重放的操作序列」，编辑器因此是有序操作列表——
一行为一条 commit/merge，行序 = 重放序 = 历史次序。画布上拖提交节点的
位置对生成代码毫无语义（重放只认顺序），是最典型的「画了不生效」假交互。

- **行字段**：类型下拉（提交/合并）、所在分支（改动即触发 branch/checkout
  自动指令——重放生成本来就按分支切换推导）、提交 ID（可空）、标签
  （tag，可空）；合并行附「合并来源」下拉（选项 = 当前行分支以外的已
  出现分支，底层维护 `mergeFrom` 边的 roleData——生成器只读它）。
- **行操作**：上移/下移（改写历史顺序）、删除；底部「＋提交 / ＋合并」
  （合并按钮在不足两个分支时禁用并提示）。
- 新合并落在最后活跃分支、来源默认另一分支——与 git 语义一致
  （在当前分支上合并自另一分支）。
