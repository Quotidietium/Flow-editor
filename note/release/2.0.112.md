## 审计范围

本轮覆盖三个面：Actions 导出并发与 PNG 尺寸输入边界（imageSize/
imageSizeMode 的 min/max 约束）、Preset 示例载入的输入管道、autoSync
状态机与 renderCount 交互。

## 缺陷与修复

**导出尺寸直通 canvas（修复 + 单测钉死）**：
PNG 尺寸输入的 `<Input min="3" max="10000">` 只是 HTML 提示——手动键入
`0`/负数会直通 `canvas.width`（0 → 静默导出空图），键入 `1e9` 触发浏
览器拒配额的巨幅画布分配（同样空图/卡顿）；且 `contentWidth=0`（隐藏
面板/viewBox 缺失）时 `ratio=Infinity/NaN` 同样直通。修复：提取纯函数
`exportCanvasSize`/`clampImageSize`（fileIO.ts，[3,10000] 夹取、非有限
值回退 1080、退化内容尺寸先收敛到 1px 使 ratio 恒有限），Actions 的
runExport 统一走该函数。fileIO.test.ts 新增 4 组 10 断言用例钉死契约
（判别性：旧内联逻辑 0→canvas 0、1e9→canvas 1e9 即违反）。

## 审计通过项

- **导出并发**：`exporting` 重入锁覆盖 PNG/SVG/复制图像入口，双击被
  挡；panZoom 关闭→干净重渲→导出→恢复的时序有 2s 兜底
- **Preset 载入管道**：`loadSampleDiagram`→`updateCode(code, {resetPanZoom,
  updateDiagram})` 走状态网关；示例内容为构建期内置/打包目录（可信
  源），无需走 URL/bridge 的插件输入管道；懒加载失败分支（r17）仍在
- **autoSync 状态机与 renderCount**：延迟渲染闭环成立——慢渲染
  （>150ms）置 `shouldSync=false` 后的下一个编辑被 1s 防抖吸收，
  `updater()` 经 `applyPartial` bump renderCount 触发 effect，本地
  code 差异使被延迟的编辑落地；纯 pan/zoom 更新被 View 的四元组
  （code/config/rough/panZoom）短路，不引发重渲；错误早退路径虽跳过
  recordRenderTime，但 debounce 回调已置 `shouldSync=true`，无死锁
